# M2 优化提案 2/3：`polish_gated_reorder`（③b 爬山 + 门控重排块）

状态：提案（M1-B 前置交付物，未动手改；供 M2 拍板）。
证据基准：REPORT §9.2/§9.3/§9.4、§10.3 聚合表；代码位 `stdraw/layout_auto.py`
分层路径 `_polish(core, edges, …)` ×2 + (row, order) 重排 + 重布线门控段。

## 现状证据

- 37 图聚合：`polish_gated_reorder` 241,783 ms = **32.1%**；随机 n10 单图占比
  97%（i00: 26.5 s / i19: 35.7 s 段内）。
- §9.4 已落 EvalCache（精确内容键 memo）：n10 墙钟 2.6×（median 56.1→21.5 s），
  polish 段占比仍 85%+ —— 剩余成本在「每个候选世界全图重布线」本身。

## 改法（两步）

1. **候选世界下界剪枝**：借 planar.py 两阶段搜索的可容许下界思路——每个
   候选世界（单节点平移 / 相邻对换）先算「受影响边子集」的局部 gate 元组
   下界；下界不可能改进当前 `_best` 的世界直接跳过全图重布线。
   下界必须可容许（只计被移动节点触碰的边的 press/clearance 变化），
   否则可能漏掉真最优。
2. **增量交叉记账**：候选世界的 crossings 全量重算改为「未受影响边对沿用
   旧值 + 受影响边对重算」，求和顺序钉死（`math.fsum` + 固定边序），
   保证与全量重算逐位一致。

## 预期收益

- n10 分层路径墙钟估 21 s → 10–14 s（再 1.5–2×；按 i00 段内 18 s 计，
  剪枝率取决于候选世界与受影响边的接触比，先跑 3 图试点测剪枝率再定）。
- 对 0 crossings 已达标图无收益（polish 不触发）——本提案只动慢腿。

## 确定性影响评估

- **中高风险**：浮点求和顺序变化是最常见的字节漂移源。增量记账必须满足
  「与全量重算的元组逐位相等」才可合入；验收 = §9.4 同款双腿 sweep
  （420 文件逐字节）+ 随机密集采样腿。
- 下界剪枝是纯枚举削减（可容许 ⇒ 幸存集含真最优），字节等价性可证；
  与 planar.py 两阶段剪枝同一先例。
