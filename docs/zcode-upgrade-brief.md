# ZCODE 升级任务书（n21–30 档算法升级，存档备用）

> 状态：**未排期，启用时以此任务书开卡**（拍板项 D3：验收数字存档备用，
> Z1/Z2 实现卡本轮不建）。本任务书不改动任何引擎代码与档位纪律；
> 档位定义见 `docs/validation-tiers.md`（§1 档位表、§4 ZCODE 档、§7 拍板记录）。

## 1. 背景

现行引擎（auto-v2，含吸附门全家桶）在 n≤20 档（A 档）已过全量逐字节门、
质量与确定性达标；但 n21–30 档（B 档）单图墙钟随节点数非线性上涨，逐字节
全量验证成本不可接受，故 B 档现状只做抽样对拍。ZCODE = 该档的算法升级工作
代号，目标 = n21–30 在红线内达到可交付质量 + 可验证耗时，达标后 B 档
逐字节门从抽样升全量（验到 30 节点）。

## 2. 边界

- **节点域**：20 < n ≤ 30。21–25 由 n30 达标自动覆盖（同算法族、耗时单调），
  不单设档。
- **A 档零漂移是硬约束**：n≤20 的 61 图（classic 21 + random n10×20 +
  n20×20）逐字节零漂移。理想实现为构造性事实（改动只在新档触发 / 关态
  等价），验证用 `benchmarks/tools/sweep_tiers.py --tier A` 双腿对拍。
- **不放宽质量口径**：证书硬门集合（压线/净距/锚点/视觉交叉语义）不变；
  grade 语义（best/3d/uncertified）不变；rc=1（诚实降级）率如实统计且
  不高于现行。

## 3. 验收数字（拍板项 D3）

对 random n30 语料 20 张全量（m = round(1.6n) 稀疏族，现行引擎口径）：

| 指标 | 目标 |
|---|---|
| 耗时 | 单图 P50 ≤ 3min、P95 ≤ 6min、max ≤ 10min，**0 例触 30min 红线** |
| 质量 | 证书硬门口径不放宽；rc=1 率不高于现行 |
| 确定性 | 输出逐字节可复现（同输入二跑 sha 全同，沿用现行口径） |
| 漂移面 | A 档 61 图逐字节零漂移（构造性事实 + sweep 验证） |

达标判定轮（ZCODE 验收轮）：n30 全 20 张 + A 档 61 图回归，本地后台分片跑，
不上 CI（`docs/validation-tiers.md` §5 频率表既有口径）。

## 4. 已知起点（实现卡开工时的输入）

- **n20 现行墙钟 ~71% 在 `anchor_snap.snap`**（85.4s/张；分段计时用
  `STDRAW_TIMING=1`，观察性、零漂移，关态双跑 sha 对拍——方法论已沉淀）。
  n30 的分布尚未实测，实现卡第一步先复测归因。
- 现行引擎 n30 单张探针 385s（6.4min，rc=1 诚实降级、产物照常落盘）——
  已贴近 P95 目标线，但为单样本且负载未隔离，以验收轮实测为准。
- n50 单张 21min 独占 / 多卡争抢 50–57min 为 C 档（>30）退役背景，不在
  本任务书范围。

## 5. 分阶段路线（每阶段独立开卡、独立验收）

- **Z1 计时归因**（~0.5 天）：复用 `STDRAW_TIMING=1` 观察性计时（零漂移
  纪律：env 开关 + stderr-only + 关态双跑 sha 对拍），产出 n21–30 墙钟
  分布表，锁定热点函数。
- **Z2 精确等价加速**（1–2 天）：只做「输出逐位一致」的优化（缓存键控、
  bbox 预过滤、增量维护三类先例），三重验证纪律（差分对拍 + 指纹对拍 +
  全语料 sha 对拍）。
- **Z3 算法级改法**（视 Z2 结果另拍板）：若 Z2 后仍超目标，评估稠密
  DEFERRED 路径在 21–30 的取舍、分层路由预算等——属行为面，另行拍板。

## 6. 开卡时的验收清单（照抄自本任务书）

1. pytest 全绿 + CI 铁门全绿（引擎行为面改动卡的标准门）。
2. `sweep_tiers.py --tier A` 双腿对拍：61 图零漂移。
3. `sweep_tiers.py --tier B`（n30 抽样 5）：抽样腿对拍通过。
4. ZCODE 验收轮：n30 全 20 张计时统计满足 §3 表（P50/P95/max/红线四项），
   原始 JSON 证据落 `benchmarks/raw/`。
5. 同输入二跑逐字节一致（确定性口径）。
