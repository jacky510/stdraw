## §2 Comparison protocol (caliber statement)

- **Same input**: same labels, same box sizes (stdraw textmetrics provides w×h px uniformly; Graphviz receives inch=px/72 with fixedsize, ELK/stdraw take px directly — all tools' native coordinates are the same physical px);
- **Threshold metrics** (box-press 1px / clearance violation 16px) are judged as absolute px in native coordinates; scale-invariant metrics (crossings/CV/row-align) are unaffected by coordinate scale; no forced scale normalization (scaling changes the physical semantics of the thresholds — being scaled down is not a quality difference); bbox additionally reported as a canvas-efficiency reference;
- **Six metrics**: crossings (strict intersection of polylines, excluding adjacent-edge pairs) / box_press (edge entering a non-endpoint box, incl. 1px margin) / clear_violations ((edge, box) pairs whose edge-to-non-endpoint-box minimum distance is <16px) / spacing_cv (std/mean of nearest-neighbor center distances) / row_align_rate (share of same-row pairs with |Δy| ≤4px) / runtime_s;
- **Metric implementation shares the same source as stdraw/metrics.py·routing.py** (directly imports seg_cross / sample_polyline / dist_point_rect); the evaluation code is public in this repo and recomputable;
- **Runtime caliber**: stdraw = in-process core layout timing (excluding parse/render/certificate); Graphviz/ELK = subprocess wall-clock (including startup overhead, slightly unfavorable to the baselines — noted honestly);
- **Budget protocol**: external budgets: ortho 60s; auto classic 300s / random n≤10 350s / random n≥20 100s; cr(G) exact layer 300s; over budget = DNF counted honestly (a DNF is not a forfeited loss — it is the fact "no layout produced within this budget"); engine-side determinism: no wall-clock deadlines (wall-clock truncation drifts with machine load and breaks byte-level reproducibility); since WS5 the n>10 CP-SAT placement uses a **deterministic time budget** (max_deterministic_time=8det, operation-count caliber — same version + same input yields the same incumbent on any machine), n≤10 and the routing layer run to proven optimality — both calibers produce byte-reproducible output;
- **auto-exact form** = reuse of the auto layout (WS2 proved byte-identical for the same input) + an independent cr(G) run; runtime = layout + exact layer;
- **Environment**: Windows 11 / Python 3.12.10 + networkx + OR-Tools CP-SAT / Graphviz 16.1.0 (official release zip, sha256-verified) / elkjs (bundled, node 22.23.2) /OGDF: not run (see §6). stdraw auto/auto-exact numbers are **re-measured after WS5** (engine b4ea801+); the baselines (Graphviz/ELK) and stdraw-ortho reuse the WS4 same-machine measurements (outside this fix's scope; engine unchanged).

## §5 stdraw auto-v2 scalability bottleneck (measured → fixed in WS5)

- **WS4 measurements (pre-fix)**: n10 took ~285s per graph (profiling: CP-SAT placement <1s; the rest went into `_polish`'s per-candidate full-graph rerouting route_all, ≈121 calls per n10 graph); n≥20 all DNF under the 100s budget, and n30/n50 did not finish under 300-420s budgets either;
- **Root-cause correction (WS5 profiling evidence; corrects the WS4 §5 attribution)**: `_polish` carries a core≤10 gate and never runs at n≥20 — it only explains n≤10 slowness and is **not** the root cause of the n≥20 DNFs; the true n≥20 bottleneck is `_cpsat_positions` **solving to global optimality** after booleanizing crossing pairs at O(m²): random-n20-i00 measured 5min+ without returning (under constructive placement route_all on the same graph took only 8.2s; n50 cold cache 410.6s);
- **WS5 fix**: ① the n>10 CP-SAT placement switched to a deterministic time budget `max_deterministic_time=8` (operation-count caliber, not wall-clock — output remains byte-reproducible; small graphs ≤10 are not budget-constrained and still prove optimality, output byte-identical to pre-fix); ② exact-equivalence speedup of the routing layer (`visibility._visible` / `routing._evaluate` bounding-box lower-bound pruning + `route_all` routed_segs incremental maintenance) — the route_all fingerprint is bit-identical; wall-clock n20 8.2→2.3s, n30 53.9→11.0s, n50 410.6→62.1s; ③ equivalence verification: classic 19 graphs + n10 sample of 2 graphs, layout.json sha256 old vs new byte-identical (21/21); `_visible` differential cross-check 3000 cases, 0 differences;

- **Dense-snap-gate wall-clock regression and fix (2026-11-10, hand-maintained correction record)**: the v0.7.15 dense snap gate (coincidence-no-worse gate + tier-2 joint detour in `Router.anchor_snap`) regressed random-n20-i00 auto-v2 from ~126s to 956.2s per run (~7.6x, over the §3 budget protocol's 100s/graph). ## §5b WS3-Q routing-quality rework (2026-11-06; root cause and fix of the 4/10 check1/check3 failures in the random n10 sample; hand-maintained correction record, NOT generated by collect.py — edited in benchmarks/manual/report-section-5b.md)

- **Symptom**: in a 10-graph sample of `corpus/random` n10, 4 graphs exited 1 with the auto recipe (check1 crossings 3~5 > gate 2; i01 additionally check3 clearance 11.6px < 16); a rerun at d483639 confirmed a pre-existing problem, not introduced by the F3 viewBox rework;
- **Root cause (measured)**: the abstract topologies of all 4 graphs are **planar** (networkx `check_planarity`, i.e. the Brandes Left-Right Planarity Test [Brandes 2009] — an earlier draft of this note misattributed it to Boyer-Myrvold) — the crossings are not a mathematical boundary but **placement-layer quality**: DAG longest-path row assignment + CP-SAT's conservative crossing proxy (skipping pairs whose endpoints share a row / whose intervals do not overlap) + weak polish pushed "topologically interleaved pairs" up to 3~11, of which greedy routing could only avoid part; plus a structural dead corner — all single-lane candidates pressed onto the mid-row y, fully blocked by the middle rows' horizontal connectors (i04's N02->N03 had all candidates with cross≥1); pass2 coordinate descent had a "mutually optimal" stalemate (each edge locally optimal per pair, pair crossings stable);
- **Fix (three hands, all deterministic, gate-triggered — layouts already meeting the routing hard gate [crossings>2 / clearance<16 / anchor violations / box-press] are untouched)**: ① layout layer: deterministic (row, within-row order) rearrangement local search (minimizing topologically interleaved pairs, cross-row moves allowed) → 24px repack → hard-gate polish (clearance/anchor hard penalties); ② routing layer: `Router(quality=True)` expands multi-row stair candidates (inter-row corridors beside the a/b rows + vertical lanes outside the middle rows' sides, structurally not entering the middle-row band); ③ joint rerouting of crossing pairs `joint_reroute` (jointly enumerating candidate combinations for the currently crossing edge pair and taking the best total score, breaking the coordinate-descent stalemate); the three hands compete with the original placement under the same gate tuple (crossing pairs / clearance violations / anchor violations / box-press);
- **Post-fix measurements (same machine, rebased on the v0.5.0 ring layout, 1f3d82f)**: all 4 failing samples exit 0 (i00 crossings 5→2), determinism verified byte-identical across two runs; random n10 sample 10/10 exit 0. v0.5.0's ring verdict intercepts 9/10 of the sample and all of classic, but `_ring_trial` carries its own hard-gate proxy and falls back to the layered path when the gate is not met — this card's gated fix takes effect on that fallback path; classic 19 graphs and the other 4 random n10 graphs (i02/i03/i07/i08/i09) are **byte-identical** relative to v0.5.0; only i06 triggered a rearrangement due to an internal gate stricter than the CLI gate (router theoretical caliber / box-press margin), producing **drift but all-pass** (crossings 2, clearance 17.5px, 0 anchor violations; determinism verified), drift recorded honestly;
- **Regression gate**: `tests/ci_checks.py` adds a B2 layer — 4 sampled graphs exit 0 + hard gate + two-run determinism assertions;
- **Boundary (honest)**: the gated rearrangement path adds ~1-2min per case (hard-gate polish's per-candidate full-graph rerouting); the random n10 family's total runtime stays within budget; n≥20 does not take the gated path (core≤10 gate), behavior unchanged; the full 80-graph random re-bench was not rerun (classic unaffected; random-family numbers per this section until the next full bench refreshes §4).
